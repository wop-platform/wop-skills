# wop-skills 意图（intent）

> 状态：grilling 定稿（2026-08-29），设计真源见 [spec.md](spec.md)
> 本文回答"为什么存在、什么算做到了"；具体设计/规格/技术选型一律在 spec.md

---

## 想法

WOP 开放平台的对接协议安全但复杂：三套件、结构化签名、L2 数字信封、12 条字节格式规则、模糊化错误（I7）——错误敏感且报错故意不说原因。6 个官方 SDK 消灭了"写调用代码"的难度，但商户仍卡在 SDK 覆盖不到的地方：密钥怎么生成上传、参数怎么排、签名为什么不过、模糊错误怎么自查。

与此同时，商户侧正在全面采用 AI agent 写代码、甚至直接执行业务操作。把平台的对接知识 + 可信工具打包成 agent skill，让 agent 替商户把对接做对。

## 愿景

- 商户工程师对 agent 说"帮我对接 WOP"，agent 按 skill 引导走完全程：选套件、生成密钥、写集成代码、跑向量自测、联调对拍定位签名差异
- 商户非技术人员对 agent 说"查一下订单 XXX"，agent 通过 skill 自带的工具完成签名→调用→验签，拿回明文结果——全程零代码
- 私钥永远不经过 agent；agent 每次执行的写操作都经过用户确认

## 目标

1. **零代码执行闭环**：agent 仅凭 skill + 用户指令，完成从环境准备到 API 调用拿到验签明文的全程
2. **开发加速闭环**：商户自研实现（任意语言）联调失败时，agent 能用官方工具对拍定位差异、沿排查树收敛到根因
3. **安全不变量**：私钥与 agent 隔离，写操作可问责——无论哪个场景、哪家 agent
4. **自验证**：skill 的正确性锚定协议真源（黄金向量），环境不对/版本漂移时拒跑而非静默出错

## 如何判断我们做到了

| # | 判据 | 验证方式 |
|---|------|----------|
| A1 | 非技术用户一句话指令 → agent 完成 API 调用并返回验签后明文，全程用户零代码、零协议知识 | 场景演练：空环境起，agent 依 skill 完成 keygen→selftest→api→call |
| A2 | 商户自研实现验签失败（I7 模糊错误）时，agent 借对拍工具定位到差异 header 或沿排查树给出下一步动作 | 注入典型错误（尾随位 `=`、DER 签名、C1C2C3 顺序）演练定位 |
| A3 | 私钥不出现在：agent 对话上下文、命令行参数、CLI 任何输出/日志 | CLI 测试断言 + argv 防御用例（疑似私钥入参必须被拒绝执行） |
| A4 | skill 在向量与真源不一致（版本漂移）时拒跑并给出明确指引 | 篡改向量 fixture 的负向量测试必须红 |
| A5 | 三 skill 安装即用：复制目录→selftest 绿→首个调用成功，无编译、无手工配置密钥格式 | 全新环境安装演练计时 |
